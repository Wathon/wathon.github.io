    Lakehouse Case Study

    2024 - 2025 | AYA Bank PCL

    Lakehouse Deep-Dive

    Enterprise Medallion Lakehouse Platform

    AYA Bank PCL • Oct 2024 - Aug 2025 • Data Platform Engineer

    Tech Stack

    Apache Spark (PySpark) Apache Iceberg Project Nessie Trino MinIO / S3 Storage Amazon EKS / K8s Apache Airflow dbt Core OpenMetadata Python SQL

    1. Context & Architecture

    Architected a Medallion Lakehouse (Bronze → Silver → Gold) to modernize core banking reporting and decouple high-load analytical queries from operational transactional databases. MinIO/S3 provided object storage, Apache Iceberg handled ACID table formats, and Trino served as the distributed federated query engine.

    2. Production Hardships & "Why the Manual is Wrong"

    • The Small File Problem in Iceberg: High-frequency batch ingestion created millions of tiny Parquet files, degrading Trino metadata lookup speeds. Solution: Engineered automated Spark compaction routines using bin-pack/sort strategies alongside scheduled snapshot expiration and orphan file cleanups.
    • Spark Executor OOMs on Container Clusters: Heavy wide-transformations and skewed data partitions triggered JVM container evictions. Solution: Tuned off-heap memory headroom (`spark.memory.offHeap.size`), optimized shuffle partitions dynamically, and applied broadcast join hints.
    • Pipeline Staging & Catalog Governance: Deployed Project Nessie to implement Git-like data branching. Engineers could stage, validate, and test ETL runs on feature branches before atomic fast-forward merges to the `main` branch, eliminating production table lockouts.

    3. Measurable Impact

    • Reduced batch reporting generation time from hours to minutes.
    • Achieved sub-second query latency for concurrent BI analytical queries over multi-terabyte datasets.
    • Established zero-loss ACID compliance, meeting central banking audit requirements.
